# Red Night v0.48.0 Parity Hardening

This milestone closes the remaining specialist-tool parity gaps identified after
v0.47.0 while preserving Red Night's explicit authorization, evidence, and
safety boundaries.

## Network and packet intelligence

### Deep protocol metadata

Red Night now includes bounded metadata dissectors for:

- HTTP request/response metadata
- TLS ClientHello metadata including SNI, ALPN and supported versions
- SSH banner/version metadata
- SMB1/SMB2 command metadata
- DNS transaction/response metadata

The dissectors return protocol metadata and fingerprints rather than arbitrary
application payload contents.

### TCP byte-stream reassembly

Deep PCAP analysis now reconstructs bounded TCP byte streams from ordered packet
segments, detects gaps/truncation, hashes reassembled content, and automatically
applies protocol dissectors to reconstructed streams.

The advanced packet CLI supports:

    red-night packet analyze capture.pcap --deep

Existing conversations, endpoint statistics, filters, suspicious-traffic
indicators, artifact extraction, and finding-to-packet evidence correlation
remain available.

## HTTPS interception and web parity

The bounded intercept proxy now supports optional HTTPS CONNECT interception.

Properties:

- loopback-only proxy listener;
- target must be within explicit Red Night scope;
- local assessment CA generated by Red Night;
- CA trust is never installed automatically;
- per-host certificates are short lived;
- generated key files are restricted where the OS supports permissions;
- HTTPS request evidence suppresses Authorization/Cookie values;
- recorded URLs strip query values and user-info;
- body content is represented by size/hash where secret-minimised metadata is
  required;
- direct HTTP/HTTPS replay remains bounded by request/response limits.

Enable with:

    red-night web-proxy --scope example.test --https-intercept

The operator is shown the generated CA certificate path and SHA-256 fingerprint.

### HTTP/2 repeater

The optional `http2` extra adds scoped HTTPS HTTP/2 replay using an
HTTP/2-capable client runtime:

    pip install -e "./packages/red-engine[http2]"
    red-night web-replay GET https://example.test/ --scope example.test --http2

The native Windows Red Night installer includes this HTTP/2 runtime.

## Reviewed controlled validation

The reviewed validation registry now contains explicit bounded proof modules for:

- TCP reachability;
- TLS certificate/protocol properties;
- HTTP policy;
- SMB signing policy;
- SSH server/identity policy;
- database metadata policy;
- identity privilege-path proof;
- cyber-range post-exploitation simulation.

Each module declares:

- family;
- proof mode;
- required service;
- preconditions;
- expected evidence fields;
- cleanup requirement;
- impact classification.

Eligibility is deterministic and reports satisfied/missing preconditions.

## Sandboxed post-exploitation and high-impact validation

High-impact behavior is represented by an isolated in-memory cyber range rather
than reusable real-world intrusion automation.

The simulator covers:

- credential-access scenarios;
- persistence scenarios;
- privilege escalation;
- lateral movement;
- propagation;
- destructive-impact scenarios;
- collection scenarios;
- bounded controlled agent sessions.

Simulation payloads are JSON/data manifests only. They declare allowed actions,
scenario ID and a step budget; they are not executable operating-system
payloads.

The range supports snapshots and automatic rollback. Every simulated action
produces an evidence ID, and a scenario report records all events plus cleanup
status and the rollback snapshot.

Example:

    red-night range-sim       --host operator:compromised:privileged       --host server       --step lateral-movement:operator:server       --step privilege-escalation:server:server       --step persistence:server:server       --step destructive-impact:server:server

No socket, subprocess, shell, filesystem mutation, service installation,
credential extraction, self-propagation, or destructive host action is exposed
by the cyber-range simulator.

## Controlled agents

Two controlled agent models are now present:

1. existing authorized read-only SSH agent sessions using reviewed fixed actions;
2. cyber-range simulated agent sessions with a small allowlisted command set.

Neither provides a reusable arbitrary remote shell.

## Professional-tool parity boundary

The following specialist workflows are now represented in Red Night:

- Nmap-class discovery/scanning/state intelligence;
- Wireshark-style packet capture, PCAP, protocol metadata, conversations,
  deep TCP reassembly and evidence correlation;
- Burp/ZAP-style interception, HTTPS CONNECT assessment, repeater, HTTP/2
  replay, crawl/DAST/API/session/parameter workflows;
- Metasploit-style reviewed eligibility, proof modules, session lifecycle,
  evidence, cleanup, and high-impact post-exploitation scenario validation;
- credentialed infrastructure and identity assessment;
- vulnerability intelligence, exploitability evidence and attack-path analysis.

Red Night intentionally does not expose unrestricted real-world credential
stealing, persistence implants, self-propagating malware, destructive
exploitation automation, or arbitrary payload/shell generation. Those
high-impact behaviors are implemented as cyber-range simulations with evidence
and rollback.
